# Модели и провайдеры в Dify

При настройке моделей в Dify нужно разделять три роли. Dify предоставляет среду приложения и подключает модель. Провайдер даёт доступ к модели через свой сервис. Модель выполняет конкретную функцию — например, генерацию текста, построение embeddings, reranking, распознавание или синтез речи.

## Кто оплачивает обращения к моделям в Dify

В Dify Cloud начать работу можно без собственного API-ключа провайдера. Для этого используются AI credits Dify, и каждый ответ модели расходует кредиты.

Другой вариант — подключить собственный API-ключ. Тогда используется аккаунт у соответствующего провайдера. Такой способ позволяет получить более высокие лимиты или оплачивать обращения напрямую через этот аккаунт. Если поставщик не поддерживается AI credits Dify, требуется собственный аккаунт у поставщика.

Таким образом, перед настройкой нужно ответить на два вопроса:

1. Поддерживается ли выбранный провайдер в Dify?
2. Будут ли обращения оплачиваться AI credits Dify или через собственный аккаунт и ключ?

## Какие типы моделей можно подключать

Тип модели определяется выполняемой функцией, а не провайдером или способом подключения:

- **языковая модель** выполняет общие задачи генерации и рассуждения;
- **embedding-модель** индексирует и извлекает содержимое базы знаний;
- **rerank-модель** переставляет найденные результаты по релевантности;
- **Speech-to-Text** преобразует аудио в текст;
- **Text-to-Speech** преобразует текст в аудио.

Один провайдер может предоставлять модели нескольких типов. Конкретную модель выбирают с учётом функции, которую она должна выполнять в приложении.

## Как подключить провайдера моделей в Dify

Провайдера моделей подключают с помощью provider plugin, установленного через `Integrations > Model Provider` или Dify Marketplace. После установки выполняют Setup: указывают API-ключ и другие параметры собственного аккаунта. Затем модели этого провайдера становятся доступны в Dify.

Единого набора параметров для всех поставщиков нет. Помимо API-ключа могут потребоваться URL сервиса, область доступа или другие значения — их проверяют в настройках конкретного плагина.

Provider plugin может быть специализированным или универсальным:

- **Специализированный плагин** содержит настройки конкретного сервиса. Например, отдельные плагины GigaChat и Ollama подключают предоставляемые ими модели.
- **OpenAI-API-compatible plugin** предназначен для целого класса сервисов с API в формате OpenAI. В нём указываются тип и название модели, API-ключ и URL сервиса. В качестве примеров документация плагина называет LM Studio и llama.cpp Service. Yandex Cloud AI Studio также предоставляет OpenAI-совместимый endpoint `https://ai.api.cloud.yandex.net/v1` и документирует вызовы через OpenAI SDK.

Специализированный и универсальный плагины — это два варианта одного механизма подключения провайдеров, а не разные типы моделей. «Локальная модель» также описывает место её запуска, а не функциональный тип: способ подключения определяется доступным API и подходящим provider plugin.

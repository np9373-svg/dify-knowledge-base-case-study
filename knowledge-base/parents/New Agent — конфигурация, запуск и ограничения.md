# New Agent: конфигурация, запуск и ограничения

New Agent в Dify — отдельный переиспользуемый AI-исполнитель с сохранённой конфигурацией. Его можно использовать самостоятельно как chat app или вызывать как этап Workflow. Если опубликованного агента подключили к нескольким Workflow, опубликованные изменения его возможностей применяются во всех этих схемах.

## Постоянная конфигурация New Agent

В разделе Configure задаются:

- роль и prompt;
- модель;
- skills;
- Dify tools;
- reference files;
- переменные окружения.

Эта конфигурация определяет возможности агента во всех задачах. Конечный пользователь опубликованного агента не может изменить его prompt, skills или подключённые функции.

@@CHILD@@

## Tools, skills и программы New Agent

Это три разных способа расширить возможности New Agent.

**Dify tools** — готовые операции из workspace: плагины, custom APIs, опубликованные Workflow и MCP servers. Их подключают в Configure, после чего агент может обращаться к ним во время работы.

**Skill** — процедура для отдельного типа задач. Его можно загрузить как пакет `.zip` или `.skill` с файлом `SKILL.md` либо поручить агенту создать skill в Build mode. Skill описывает порядок работы; Dify tools и справочные файлы подключаются к агенту отдельно и не должны помещаться внутрь skill-пакета.

**Программы в sandbox** не обязательно должны быть заранее оформлены как Dify tools. New Agent может выполнять команды и самостоятельно устанавливать command-line программы в своём sandbox. Если программа установлена в Build mode и изменения применены, она становится частью сохранённой конфигурации. Программа, установленная во время обычного опубликованного запуска, доступна только в этом запуске.

@@CHILD@@

## Prompt и Task в New Agent

Prompt задаёт постоянную роль агента, общий способ работы, правила использования функций и формат ответа. Task — поручение для одного запуска.

При самостоятельной работе Task передаётся сообщением пользователя. В Workflow задача задаётся в Agent node и может включать данные предыдущих узлов. Новая задача не изменяет постоянную конфигурацию агента.

@@CHILD@@

## Как работает агентский цикл New Agent

Task запускает отдельный agent run. Внутри него New Agent работает циклически:

1. модель получает задачу и постоянные инструкции агента;
2. выбирает следующее действие — сформировать ответ, вызвать Dify tool или выполнить действие в sandbox;
3. Dify выполняет выбранное действие и возвращает результат в контекст агента;
4. модель оценивает результат и либо продолжает работу, либо формирует итоговый ответ.

Поэтому один run может включать много обращений к модели и инструментам. Цикл заканчивается итоговым результатом, ошибкой или достижением лимита запуска.

Разработчик влияет на цикл через модель, Prompt, Task, skills, доступные Dify tools, файлы, переменные окружения и программы в sandbox. Сам цикл выполняется runtime автоматически. Текущая документация New Agent не описывает пользовательские настройки выбора Function Calling или ReAct, максимального числа итераций либо собственного условия остановки. Эти параметры нельзя считать настраиваемыми без дополнительного подтверждения.

@@CHILD@@

## Способы запуска New Agent

Самостоятельный New Agent получает задания через опубликованное web app или Service API. Внутри Workflow опубликованный агент подключается через Agent node и выполняет один этап общей схемы.

Каждый опубликованный запуск или вызов из Workflow получает отдельный sandbox на основе сохранённой конфигурации агента.

@@CHILD@@

## Что сохраняется между запусками New Agent

| Данные | Сохраняются для следующих задач |
|---|---|
| Prompt, модель, skills, Dify tools, reference files и переменные окружения | Да, как конфигурация агента |
| Файлы и программы, сохранённые через Build mode | Да, после применения изменений |
| Файлы, программы и другие изменения обычного запуска | Нет, существуют только в этом запуске |
| История сообщений | Только внутри текущей беседы и контекстного окна модели |

Новая беседа самостоятельного New Agent начинается без истории предыдущей беседы. При этом постоянная конфигурация и сохранённые ресурсы остаются доступными.

@@CHILD@@

## Создание, настройка и обновление New Agent

New Agent создают на странице Agents с нуля или импортируют из DSL-файла. Для создания и управления агентами требуется роль Editor или выше. DSL переносит конфигурацию не полностью: skills и файлы после импорта нужно добавить отдельно.

Возможности агента можно настроить вручную в Configure или сформировать вместе с агентом в Build mode. Во втором случае разработчик описывает желаемое поведение сообщениями, а агент создаёт skills, файлы, переменные окружения и при необходимости устанавливает программы в sandbox. Применённые изменения и постоянные файлы становятся частью конфигурации будущих запусков.

Изменения автоматически сохраняются в черновике. Публикация делает подготовленную версию активной. История версий позволяет вернуться к предыдущей конфигурации; вместе с версией восстанавливаются сохранённые файлы sandbox. Workflow, в которых подключён опубликованный агент, получают его опубликованные обновления.

@@CHILD@@

## Лимиты одного запуска New Agent

Один запуск New Agent останавливается через один час независимо от точки запуска: web app, Service API или Workflow. На один запуск также действует лимит в 500 обращений агента к модели. Следующее сообщение самостоятельному агенту или новый вызов Agent node создаёт отдельный запуск со своими лимитами.

# Узлы Workflow и Chatflow для выполнения действий

Узлы Dify не взаимозаменяемы. Выбор зависит от того, что именно нужно сделать, кто определяет момент и способ действия, какие данные должны поступить на вход и что требуется получить на выходе.

## HTTP Request: прямой вызов внешнего API

HTTP Request подключает workflow к внешнему API или web-сервису. Параметры запроса задаются непосредственно в узле, а вызов выполняется автоматически, когда схема до него доходит. Модель не принимает решение, нужно ли вызывать этот API.

Такой вариант подходит для разового или нестандартного обращения, например для очистки, проверки или обогащения данных. Если внешний API недоступен, для HTTP Request можно настроить fallback-ветку.

## Tool node: заранее выбранная операция

Tool node выполняет конкретную готовую операцию. Источником операции может быть Tool Plugin, custom tool из OpenAPI, опубликованный Workflow или MCP server.

Положение Tool node в схеме заранее определяет момент вызова. Модель не выбирает операцию: разработчик уже указал её в узле. В отличие от прямого HTTP Request, tool представляет собой подготовленную переиспользуемую возможность, доступную в workspace.

@@CHILD@@

## Code node: локальная обработка данных

Code node выполняет собственную логику на Python или JavaScript. Он подходит для очистки текста, преобразования JSON, вычислений и другой локальной обработки данных.

Sandbox Code node блокирует исходящие сетевые запросы, доступ к файловой системе и системные команды. Поэтому Code node не заменяет HTTP Request или Tool node для обращения к внешнему сервису.

@@CHILD@@

## Document Extractor: файл в текст

Document Extractor преобразует загруженные файлы в текст, который затем может обработать LLM. Его задача ограничена извлечением текстового содержимого для следующих шагов. В собранных фактах нет перечня поддерживаемых форматов или дополнительных параметров извлечения, поэтому такие детали требуют отдельной проверки.

## Agent node и Classic Agent node

Опубликованный New Agent можно подключить через Agent node как один из этапов workflow. Агент получает задачу из настроек узла. Сам workflow может быть запущен пользователем или автоматически — по расписанию, webhook либо событию интеграции.

Classic Agent node доступен в Workflow и Chatflow. В нём настраиваются модель, стратегия Function Calling или ReAct, доступные функции, инструкции, контекст и максимальное число итераций. В отличие от обычного узла, здесь модели передаётся выбор действий: она определяет, какие функции использовать, когда и как их вызывать и нужно ли продолжать работу после получения результата.

Заранее неизвестная последовательность вызовов — характерный сценарий Classic Agent node, но не ограничение его возможностей. Агент может выполнить и один вызов; критерий выбора состоит в том, должен ли способ действия определить разработчик в схеме или модель во время выполнения.

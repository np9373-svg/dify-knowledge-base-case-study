# Как устроен RAG в Dify
## Что такое RAG

RAG — это подход, при котором приложение сначала находит сведения в базе знаний, а затем использует их при формировании ответа языковой модели.

@@CHILD@@

## Что происходит в RAG до запроса пользователя

Сначала из источников создают **Knowledge Base** (базу знаний) для поиска:

`источники → обработка → chunks → индекс`

**Chunk** — отдельный фрагмент содержимого. **Индекс** — подготовленное представление таких фрагментов, по которому система может находить подходящие сведения.

Knowledge Base описывает, какие подготовленные знания доступны приложению и как по ним выполняется поиск. Для хранения и поиска могут использоваться разные технические решения. Например, в self-hosted Dify векторным хранилищем может быть Weaviate, Qdrant, Milvus или pgvector. Примеры поисковых индексов — векторный индекс на основе embeddings и инвертированный индекс по ключевым словам. Хранилище и индекс являются частью технической реализации Knowledge Base, но не равны всей базе знаний.

## Что происходит в RAG при запросе

После запуска приложения выполняется другая последовательность:

`запрос → поиск → найденные chunks → контекст LLM → ответ`

**Retrieval** — поиск подходящих chunks в базе знаний по запросу пользователя. Приложение не передаёт модели всю базу целиком: узел Knowledge Retrieval находит связанные с запросом фрагменты и передаёт их LLM как дополнительный контекст для ответа.

# Tools, API и внешние интеграции в Dify

Интеграции Dify работают в двух направлениях. В первом приложение Dify обращается к внешнему сервису, получает данные или выполняет действие. Во втором внешний backend вызывает опубликованное приложение, workflow или базу знаний Dify через REST API.

Разделение направлений помогает не смешивать два разных вопроса: как дать приложению внешнюю возможность и как встроить само приложение в другую систему.

## Когда Dify обращается к внешнему сервису

Dify tools — подключаемые операции, управляемые на уровне workspace. Через них приложения и LLM обращаются к внешним сервисам и API, получают актуальные данные или выполняют действия.

Tool выделяет внешнюю возможность в переиспользуемую операцию с определёнными параметрами. После подключения её можно применять в разных приложениях без повторного описания одного и того же API-вызова внутри каждой схемы.

## Откуда берутся Dify tools

В Dify предусмотрено несколько источников:
1. Tool Plugin — готовая интеграция или функция из Dify Marketplace. Плагин предоставляет одну или несколько операций, например web-поиск или обращение к популярному сервису, и может хранить необходимые учётные данные.
2. Custom tool из OpenAPI. Custom tool подключает существующий внешний API к workspace. Dify создаёт доступные операции и их параметры из OpenAPI-описания.
3. Опубликованный Workflow. Workflow с User Input можно превратить в tool. Так многошаговая логика становится переиспользуемой операцией для других приложений.
4. MCP server — внешний поставщик возможностей по единому протоколу. Он может предоставлять инструкции, данные и исполняемые функции.

## Где вызываются Dify tools

В Workflow и Chatflow tool можно вызвать через Tool node. Здесь конкретная операция выбрана заранее, а её позиция в схеме определяет момент выполнения.

Tools также доступны Classic Agent node, New Agent. В агентском сценарии подключённые операции входят в набор возможностей агента.

## Чем Dify Tools отличается от HTTP Request

HTTP Request — прямой вызов внешнего API или web-сервиса с параметрами, заданными непосредственно в узле. Он выполняется автоматически, когда workflow достигает этого шага; модель не решает, нужен ли вызов.

Такой узел подходит для разовой или нестандартной интеграции. Tool, напротив, представляет подготовленную переиспользуемую операцию на уровне workspace. Поэтому повторяемую возможность логично оформлять как tool, а единичный фиксированный вызов можно оставить в HTTP Request. Это практическое различие следует применять с учётом масштаба повторного использования, а не считать техническим запретом.

## Когда внешний backend вызывает Dify

Опубликованные приложения, workflows и базы знаний Dify доступны через REST API. Для Dify Cloud используется базовый URL `https://api.dify.ai/v1`. Для self-hosted установки применяется API URL собственного экземпляра.

Конкретную опубликованную версию workflow можно запустить через Service API по её `workflow_id`. Таким способом внешний backend передаёт входные данные в Dify и получает результат опубликованной логики.

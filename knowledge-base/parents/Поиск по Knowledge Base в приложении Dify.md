# Поиск по Knowledge Base в приложении Dify

Knowledge Retrieval связывает базу знаний с Workflow или Chatflow. Он получает запрос, находит подходящие chunks в одной или нескольких базах и передаёт результат следующим узлам. Одна база может использоваться в разных приложениях Dify.

## Как ограничивается область поиска в Knowledge Base

Во встроенной Knowledge Base **metadata filtering** ограничивает поиск документами, значения metadata которых соответствуют условиям — например, нужной категории, источнику, автору или дате. После этого retrieval ищет среди chunks выбранных документов.

Для External Knowledge Dify может программно передать условия `metadata_condition` внешнему endpoint. Внешняя система сама интерпретирует эти условия по своей схеме metadata, выполняет поиск и возвращает chunks вместе с доступными metadata. В интерфейсе Dify настройка этих условий для External Knowledge сейчас не предоставляется.

Затем узел обращается к одной или нескольким выбранным Knowledge Bases. Если баз несколько, поиск выполняется по ним параллельно, а результаты объединяются.

## Как выполняется первичный поиск в Knowledge Base

В зависимости от конфигурации используются разные подходы:

- **Vector Search** сопоставляет смысл запроса и chunks по векторам;
- **Full-text Search** ищет совпадения по словам;
- **Hybrid Search** сочетает семантический и полнотекстовый поиск;
- **Inverted Index** ищет по ключевым словам в режиме Economical.

Этот этап формирует набор кандидатов. Он ещё не определяет окончательный контекст для модели.

## Reranking и ограничения результата

**Reranking** — повторная оценка уже найденных chunks относительно запроса. Он может использовать взвешивание семантического и словарного совпадения либо отдельную rerank-модель. Такая модель работает на этапе поиска и не создаёт хранимые embeddings.

После объединения и reranking применяются:

- **Top K** — сколько лучших chunks оставить;
- **Score Threshold** — ниже какой оценки результат исключить.

Итоговая последовательность выглядит так:

`запрос → metadata filtering → первичный поиск → объединение → reranking → Top K и порог → chunks`

## Как chunks из Knowledge Base попадают в ответ

Knowledge Retrieval возвращает найденные chunks следующим узлам. LLM node использует их как контекст при подготовке ответа. В Chatflow рядом с ответом могут показываться citations: они указывают использованные источники, но сами по себе не подтверждают, что поиск выбрал лучший фрагмент.

## Дополнительная логика вокруг Knowledge Retrieval

Workflow или Chatflow может преобразовать запрос, определить тему и выбрать базу **до** Knowledge Retrieval, а после него — обработать результаты, решить, передавать ли их модели, или выполнить fallback. Эти узлы расширяют схему приложения, но не вставляются внутрь алгоритма Knowledge Retrieval.

Если нужен полностью собственный retrieval, его выносят во внешнюю систему и подключают через External Knowledge либо вызывают по HTTP/API.

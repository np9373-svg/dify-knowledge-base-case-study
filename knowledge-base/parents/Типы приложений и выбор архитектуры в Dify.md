# Типы приложений и выбор архитектуры в Dify

Архитектуру Dify выбирают не из плоского списка типов. Сначала нужно определить, является ли вся задача открытой или её можно описать как процесс. Если процесс известен, выбирают Workflow или Chatflow, а затем решают, нужны ли внутри схемы агентские этапы и каким типом агента их реализовать.

## Самостоятельный New Agent или схема

**New Agent** подходит для открытой задачи, в которой последовательность действий зависит от поручения и промежуточных результатов. Он существует как самостоятельный AI-исполнитель с сохранённой конфигурацией, sandbox, skills, файлами и Dify tools. Агент может запускать команды, устанавливать программы и работать с файлами. Если заранее заданного процесса нет, создавать Workflow ради одного агентского узла необязательно.

**Workflow или Chatflow** выбирают, когда общий процесс можно описать заранее. Узлы и переходы фиксируют обязательные этапы, движение данных и ветвления. При этом отдельные открытые части работы можно передавать агентам, сохраняя общую управляемую схему.

## Workflow или Chatflow

Workflow и Chatflow используют общую визуальную схему и систему узлов, но отличаются режимом взаимодействия.

**Workflow** выполняется один раз от входных данных до результата. Он подходит для однократного запуска процесса.

**Chatflow** предназначен для диалога: каждое сообщение пользователя запускает спроектированный flow до формирования ответа. Между сообщениями одной chat session могут сохраняться conversation variables.

Самостоятельный New Agent также получает задания сообщениями и сохраняет историю внутри текущей беседы и контекстного окна модели. Поэтому выбор определяется не просто наличием диалога: New Agent — это автономный исполнитель открытых задач, а Chatflow — диалоговое приложение с заранее спроектированной схемой обработки каждого сообщения.

## Нужен ли агент внутри схемы

Если все этапы и переходы можно определить заранее, процесс собирают из обычных узлов Workflow или Chatflow. Агентский этап нужен там, где порядок действий зависит от содержания подзадачи, полученных ответов и условий, которые нельзя полностью предусмотреть в схеме.

Такой подход сочетает предсказуемость общего процесса с автономностью отдельных исполнителей.

## New Agent или Classic Agent node

**New Agent** выбирают, когда агент должен быть отдельным и переиспользуемым. Его конфигурация хранится независимо от конкретной схемы, а опубликованного агента можно подключать к разным workflow через Agent node. New Agent предоставляет sandbox, skills, файлы и Dify tools. Разработчик задаёт возможности, постоянные инструкции и Task, но внутренним циклом обращений к модели и инструментам управляет runtime. Текущая документация не описывает для New Agent пользовательский выбор Function Calling или ReAct, Max Iterations либо собственного условия остановки. Следующий узел по умолчанию получает текстовый результат агента либо явно объявленные значения и файлы; подробные логи просматриваются отдельно.

**Classic Agent node** выбирают, когда агентская конфигурация относится к конкретному Workflow или Chatflow или разработчику нужно сильнее влиять на агентский цикл. Непосредственно в узле задаются модель, функции, инструкции и контекст, выбирается стратегия Function Calling или ReAct и устанавливается Max Iterations. Узел также предоставляет схеме структурированные результаты вызовов функций, трассировку, число итераций, статус и логи.

## Дерево выбора архитектуры в Dify

1. Можно ли заранее определить общий процесс?
   - Нет — используйте самостоятельный New Agent.
   - Да — постройте схему Workflow или Chatflow.
2. Нужен ли диалог по заранее спроектированной схеме?
   - Да — выбирайте Chatflow.
   - Нет, нужен один запуск от входных данных до результата — выбирайте Workflow.
3. Есть ли внутри схемы открытая подзадача с заранее неизвестной последовательностью действий?
   - Нет — используйте обычные узлы.
   - Да — добавьте агентский этап.
4. Каким должен быть агентский этап?
   - Отдельным, переиспользуемым, с sandbox и skills, но автоматически управляемым циклом — подключите New Agent через Agent node.
   - Настраиваемым внутри схемы, с выбором стратегии, Max Iterations и подробными структурированными выходами — используйте Classic Agent node.

Workflow или Chatflow координирует общий процесс, а подключённые агенты самостоятельно выполняют порученные им открытые задачи.

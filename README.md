# Dify-ассистент для новичков

Практический кейс проектирования базы знаний для RAG-ассистента: от пользовательских задач и проверенных фактов до Parent-Child документов и минимального Chatflow в Dify.

**[Открыть ассистента](https://udify.app/chat/f6PaUk9HZesp0r7O)**

## Что это за продукт

Ассистент помогает новичку понять возможности и ограничения Dify, выбрать тип приложения, модель, базу знаний и подходящий способ интеграции. Он объясняет концепции и помогает принять первое архитектурное решение, но не заменяет полную техническую документацию или проектирование production-системы.

## Статус проекта

Это MVP и методологический кейс. Репозиторий показывает продукт, устройство базы, принятые архитектурные решения и воспроизводимый Chatflow. Рабочие исследовательские таблицы и формальные сравнительные прогоны пока не публикуются; поэтому выводы о промпте и retrieval сформулированы как решения этого проекта, а не как универсально доказанные правила.

## Главный тезис

Рабочий тезис проекта: в RAG-ассистенте качество ответа во многом определяется не сложностью workflow, а тем, насколько хорошо база знаний спроектирована под пользовательские задачи и последующий поиск.

В этом проекте основная работа была выполнена до запуска модели:

1. Зафиксированы вопросы, боли и решения пользователей.
2. Из официальной документации собраны проверяемые атомарные факты.
3. Факты объединены в смысловые темы.
4. Для каждой темы спроектирован родительский документ и его дочерние разделы.
5. На основе исходных вопросов сформированы проверочные сценарии для retrieval и ответа.

## Что получилось

- 37 исходных пользовательских вопросов, которые задали направление сбора фактов и проектирования базы.
- Рабочий реестр атомарных фактов, собранных по официальной документации Dify.
- 15 тематических Parent-Child документов.
- Простой Chatflow: `Start → Knowledge Retrieval → LLM → Answer`.
- Векторный поиск без reranking и Full-Text Search, `Top K = 3`.
- Ссылки на использованные документы базы через функцию Citations в Dify.

## Минимальный промпт — это результат, а не недостаток

В ходе ручных итераций сложные инструкции делали ответы более механическими и менее содержательными. Поэтому в MVP оставлен короткий промпт: он задаёт роль, язык, принцип отбора релевантного контекста и честное поведение при нехватке данных.

Это проектное решение для данного ассистента, а не универсальное правило для любого AI-приложения. Формальное сравнение версий промпта в MVP не публикуется.

## Архитектура

```text
Вопрос пользователя
        │
        ▼
Knowledge Retrieval
  поиск по child-разделам
  возврат parent-документов
        │
        ▼
LLM + минимальный prompt
        │
        ▼
Ответ + Citations
```

Каждый родитель хранится как отдельный Markdown-документ. Внутри него дочерние разделы отделены маркером `@@CHILD@@`.

## Как воспроизвести

1. Импортируйте [`dify/app.yml`](dify/app.yml) в Dify Studio.
2. Создайте Knowledge Base с Parent-Child chunking.
3. Загрузите в неё файлы из [`knowledge-base/parents`](knowledge-base/parents).
4. Настройте `@@CHILD@@` как разделитель дочерних чанков.
5. Подключите созданную базу в Knowledge Retrieval node.
6. Сверьте параметры с [`dify/import-and-run.md`](dify/import-and-run.md).
7. Прогоните вопросы из [`evaluation/test-cases.md`](evaluation/test-cases.md).

Экспорт приложения ссылается на внешнюю Knowledge Base по `dataset_id`, но не содержит саму базу и её активные retrieval-настройки. Поэтому базу нужно создать и подключить отдельно.

## Ограничения

- База знаний ограничена выбранными задачами новичков и не заменяет всю документацию Dify.
- Качество зависит не только от базы, но и от модели, retrieval, промпта и набора тестов.
- Это учебный проект; в нём используются только публичные и тестовые данные.

# Проверочные сценарии

Этот короткий набор позволяет ревьюеру быстро проверить ключевые свойства ассистента. Исходные исследовательские таблицы в MVP не публикуются: они помогали определить содержание базы, но не являются согласованным benchmark.

| Тип | Вопрос | Ожидаемое поведение |
| --- | --- | --- |
| Базовый | Что такое Dify и когда он мне нужен? | Объясняет назначение платформы и критерий выбора, не пересказывая весь документ. |
| Выбор архитектуры | Мне нужен бот с памятью диалога. Workflow или Chatflow? | Рекомендует Chatflow и объясняет роль conversation variables. |
| Перефразировка | У меня есть документы. Как сделать, чтобы бот отвечал по ним? | Находит материал о Knowledge Base и RAG, даёт понятную последовательность. |
| Составной | Как собрать FAQ-бота и потом проверить, что он ищет правильно? | Соединяет материал о Chatflow/RAG и Retrieval Testing. |
| Граница знания | Какой SLA у актуального Enterprise-тарифа Dify? | Не придумывает SLA, сообщает о нехватке данных и предлагает проверить актуальный источник. |
| Точный термин | Чем HTTP Request node отличается от Tool node? | Различает фиксированный API-вызов и заранее описанную tool-операцию. |
| Ограничение | Что сохранится, если я запущу новую беседу? | Различает контекст текущей беседы и постоянное внешнее хранилище. |
| Citations | Как устроен RAG в Dify? | Даёт ответ по базе и показывает использованные документы Knowledge Base. |

## Как фиксировать результат

Для каждого вопроса стоит записать:

1. какие parent-документы вернул retrieval;
2. был ли среди них нужный материал;
3. использовала ли модель нужные факты;
4. добавила ли она неподтверждённые утверждения;
5. был ли ответ полезен для исходной задачи;
6. отобразились ли Citations.

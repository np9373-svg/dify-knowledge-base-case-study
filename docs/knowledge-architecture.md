# Архитектура базы знаний

## Почему Parent-Child, а не Q&A

Q&A подходит, когда единицы ответа небольшие, самостоятельные и стабильные, а запросы достаточно предсказуемы.

В этом проекте пользователи могут задавать много разных вопросов об одной сущности или решении. Для точного ответа часто нужен контекст соседних разделов. Parent-Child позволяет:

- искать по точным дочерним фрагментам;
- возвращать модели связный родительский контекст;
- не дублировать одни и те же факты в множестве пар «вопрос — ответ»;
- обновлять материал как смысловую единицу.

## Критерии хорошего родителя

1. Все ли дочерние разделы относятся к одной сущности или одному решению?
2. Нужна ли большая часть родителя для понимания каждого ребёнка?
3. Не окажется ли 70–80% возвращённого текста посторонним для детального вопроса?
4. Можно ли обновлять этот материал как одну смысловую единицу?
5. Можно ли однозначно назвать основной вопрос, на который отвечает родитель?

Если последний вопрос получает несколько независимых ответов, родитель, вероятно, слишком широк.

## Физическая структура

```markdown
# Заголовок родителя

Краткое введение.

## Первый дочерний раздел

Связный фрагмент знаний.

@@CHILD@@

## Второй дочерний раздел

Следующий фрагмент.
```

Разделитель сделан явным, чтобы нарезка в Dify не зависела от эвристик по длине или знакам пунктуации.

## Почему один родитель — один документ

Такая схема:

- делает границы тем видимыми;
- упрощает загрузку и замену материала;
- позволяет обновлять темы независимо;
- даёт понятное имя источника для Citations.

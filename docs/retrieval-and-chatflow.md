# Retrieval и Chatflow

## Схема приложения

```text
Start → Knowledge Retrieval → LLM → Answer
```

Вопрос пользователя без предварительной классификации передаётся в Knowledge Retrieval. Найденные родительские документы поступают в context LLM. Модель формирует ответ, а Dify через Citations показывает документы Knowledge Base, использованные при ответе.

## Активные настройки Knowledge Base

| Параметр | Значение |
| --- | --- |
| Chunk Structure | Parent-Child |
| Embedding model | `text-embedding-3-small` |
| Retrieval method | Vector Search |
| Top K | 3 |
| Rerank model | Disabled |
| Score threshold | Disabled |
| Full-Text Search | Disabled |
| Child separator | `@@CHILD@@` |

## Почему без Full-Text Search

Ассистент помогает понять концепции и выбрать вариант решения. Пользователи формулируют одну и ту же задачу по-разному, поэтому для MVP выбран семантический поиск. Full-Text Search не включён: его преимущество для этого понятийного корпуса ещё не подтверждено отдельной сравнительной оценкой.

Это решение не является универсальным. Для кодов ошибок, API-полей, редких имён и точных технических терминов гибридный поиск может оказаться лучше.

## Почему без reranking

Для небольшой базы выбран `Top K = 3`. Reranking отключён, чтобы сначала оценить базовую связку из структуры корпуса и векторного поиска. Его полезность для этого корпуса ещё не проверена отдельным сравнительным тестом.

## Почему этого достаточно для MVP

Это минимальная воспроизводимая конфигурация для проверки основного тезиса проекта. Усложнять retrieval стоит после фиксации конкретных ошибок: например, плохого ранжирования, пропуска точных терминов или слишком большого объёма лишнего контекста.
